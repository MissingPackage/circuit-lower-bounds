======================================================================
PART 1. ENCODING (design)
======================================================================
E1 One SAT instance per (certificate node, identification partition of the
   node's full pattern). The partitions and the static pattern facts (kinds,
   types, out-degree ranges, protected flags, partners, edges, no_edge,
   sum_ge) are taken from the WP3.1 code (checker.initial_comps), so both tools
   start from the same pattern semantics. A node is SAT if one partition is.

E2 Universe = a pool of node slots, three blocks:
   - pattern slots (one per partition block);
   - block A: the level-1 nodes (neighbours of pattern nodes). Its size is a
     static bound computed from the pattern (free input slots of pattern
     gates + free successor slots of pattern nodes up to the degree cap), so
     block A can never be too small (hand-argument);
   - block B: everything else (level >= 2), F_B slots (a run parameter), plus
     a small partner block for partners of pattern variables.
   Per slot: used, var/gate, gate type (and/xor), the two and-type bits (the
   input value that trivialises the gate, as in engine.py), exact out-degree
   od in 0..cap (cap 3, as in WP3.1), protected flag, partner pointer (pool
   variable or "outside"), full/stub flag for gates. A full gate has two input
   pointers into the pool; a stub gate has unrevealed inputs. Hidden
   successors: ext(v) = od(v) - (number of full pool gates reading v) >= 0.
   Acyclicity by an order-encoded rank. The original circuit is normalized on
   the revealed part: no gate reads one node twice, no N4 configuration, at
   most one 0-gate (the output), pattern constraints, and the triggers of the
   earlier cases (the node's 'pre' list, as in WP3.1) are forbidden on the
   revealed part (an over-approximation of the completion set: sound for
   UNSAT; hand-argument).
   All pattern gates and block-A gates are full; all pattern nodes have all
   successors revealed (ext = 0). Eligible gates for normalization = pattern
   gates + block-A gates = the gates at distance <= 1 from the pattern, the
   same radius R = 1 as WP3.1 (the certificates do not set 'radius').

E3 Simulation, one copy per (action of the node or of an ancestor, choice of
   the trivialising constants): after each substitution step, the fixpoint
   of Transformations 1, 2, 3, 5 on the eligible gates, computed
   declaratively: a forward pass in rank order (each gate's inputs resolved
   through removed gates: alive -> itself, constant-removed -> the constant,
   passing-removed -> its passed input with the polarity folded in; then
   classification const / passing / identical-inputs / alive), and a
   backward pass for Transformation 1 (an eligible gate with no surviving
   successor that is not the output). For Transformations 1, 2, 3, 5 the
   fixpoint does not depend on the order of application (hand-argument:
   forward degeneracy flows from inputs to outputs, Transformation 1 only
   removes successor-less gates). Multi-step actions: one pass per step, the
   removal kind of a gate removed at step k is frozen for later steps (as in
   the sequential engine, where a passing-removed gate cannot later be
   'trivialised').
   Transformation 4 is NOT applied after substitutions in the first version
   (sound: under the trust assumption A0 below every state reached by valid
   transformations gives a valid lower bound; lossy: it may produce spurious
   SAT answers, which the replay detects).
   Substitutions: x <- c, x <- t + c (t an input), z <- (u+a)(v+b)+c computed at
   an and-gate whose current inputs are two unprotected variables (FGHK S1,
   S2, S4 as transcribed in the WP3.1 pre-registration). Legality as in
   engine.py (influential substituted variable; no affine/quadratic
   substitution of a protected variable; quadratic source an alive and-gate
   fed by two unprotected input variables not including the substituted one).
   A trivialisation target must be removed by Transformation 2 at or before
   its step. The output: a gate of out-degree 0; if it becomes constant (or a
   substituted variable is the output) the completion is vacuous and is not
   a counterexample (FGHK p.22, the only disperser property used, as WP3.1).

E4 Measure decrease (per simulation), two accountings as in engine.py:
   - conservative (sound on any revealed part, Prop. 3.4.2/3.4.3/Lemma 3.5.1):
     g = removed eligible gates, p = pending (revealed non-eligible gates that
     read a constant or one node twice, or became 0-gates), i = influential
     inputs lost minus gained, q = quadratic equalities removed (const on a
     protected variable +1, quadratic substitution -1), and
     Delta t >= -4 g - (Prop. 3.4.2 term of engine.py);
   - exact: Delta t = troubled before - troubled after over the revealed full
     gates, valid only if every requirement R1/R2 below is met.
   Gain form (1, aT, aI, aQ) = (g + p, Delta t - 4 p, i, q), compared with the
   claimed type's linear form for ALL admissible alphas (0 <= aT <= 1/4,
   aI, aQ >= 0) exactly, as engine.dominates does: the counterexample side
   asks for a point of the region where the gain is strictly below the type.
   Alphas are quantified over the region, not fixed to FGHK's values.

E5 Requirements (what must be revealed for exact accounting):
   R1 every successor of a node that is removed, substituted, or (variables)
      whose out-degree changes with old or new value 2, is a revealed full
      gate (ext = 0);
   R2 every gate whose out-degree changes is full.
   Capacity: block B may be too small. A model may leave a requirement unmet
   only if every block-B slot is used, every used block-B slot is justified
   (an input of a full gate, a full gate reading an R1 node, or a partner),
   and then only the conservative accounting may credit an action. Such a
   model is reported as OVF (pool too small), never as a counterexample.
   Soundness of UNSAT for every completion in the WP3.1 model (acyclic,
   out-degree cap 3) regardless of F_B: hand-argument [VERIFY] (a violating
   completion either has a closed revealed part that fits, giving a normal
   model, or a justified truncation that fills block B, giving an OVF model).

E6 Counterexample instance for a leaf: some partition and completion such
   that no simulation is vacuous and every (action, constants) of the node
   and of its ancestors (inherit chain, as WP3.1) fails: illegal, or a target
   not trivialised, or the gain below every claimed type of that action.
   UNSAT = leaf certified (for the partition set, cap 3, R = 1).
   Exhaustiveness instance for an internal node: the same plus "no child
   matches" (child patterns, unions expanded, with the node's declared
   symmetries, matched on the revealed part with the shared names fixed, as
   checker.analyse does). All child-pattern nodes used in Cases 1-5 are within
   distance 1 of the parent pattern, hence revealed (hand-argument, checked
   per certificate by the encoder: it refuses a child with a node it cannot
   force into the revealed part).

E7 Symmetry breaking (completions up to isomorphism): fresh slots inside a
   block are interchangeable; consecutive slots are ordered non-increasingly
   by the lexicographic order of a signature (used, gate, adjacency to the
   pattern slots, and for block B also to block A). This is a prefix of the
   lex-leader constraint for each adjacent transposition, hence sound
   (hand-argument). Partitions of the pattern are enumerated outside the
   solver (first-use canonical, as WP3.1).

E8 Solver: python-sat, CaDiCaL 1.9.5 ('cadical195'), from the project .venv,
   one call per instance, hard timeout 600 s per certificate (reported as
   timeout). DRAT proofs are emitted for UNSAT answers (written to
   wp3/logs/wp32/proofs/, possibly compressed). An external checker is used
   only if one can be installed without network; otherwise drat_status =
   'unsat-uncertified'.

E9 Replay (independent check of every SAT answer): the model is converted to
   a WP3.1 engine completion (gecheck.engine.Comp) holding exactly the
   revealed facts; the WP3.1 engine then runs its own analysis (checker.
   analyse, admissibility, pre triggers) and its lazy DFS over the facts the
   model left open, with a time budget. Verdict 'violation' if the engine
   finds a completion it does not discharge (leaf) or does not cover
   (internal node); 'not-a-violation' if it discharges/covers every branch;
   'undecided' on timeout. A SAT answer replayed as not-a-violation is an
   encoder bug (spurious), not a finding. engine.py and checker.py are not
   modified (they are the oracle).

E10 No code path keyed to a case label (as WP3.1); everything case-specific
    comes from the JSON certificates. Certificates unchanged.

E11 Output: one file per certificate and per control, wp3/logs/wp32/<id>.json,
    written as soon as it finishes, with status (UNSAT / SAT / OVF / timeout),
    solve_s, encode_s, n_vars, n_clauses, certified (claimed) types,
    drat_status, per-partition details, and for SAT the counter-completion
    and the engine replay verdict. Progress printed while running.

E12 Trust assumptions (inherited from WP3.1, not re-proved): Prop. 3.4.2,
    Prop. 3.4.3, Lemma 3.5.1 (read-with-page p.16-21 via WP3.1), and
    A0: every state reached from the substituted circuit by valid
    transformations gives a lower bound on the decrease of mu after FGHK's
    ordered normalization (WP3.1 relied on the same when restricting to
    radius 1 and skipping undecidable N1/N4; inferred [VERIFY]).
    Declared limits: out-degree cap 3, acyclic completions, radius 1.

Kill criteria (verbatim from the WP brief): a negative control that comes out
UNSAT (encoder too strong) or a verified leaf that comes out SAT with a
replayed real violation that survives a second reading of the paper (a
finding, reported with the pattern, never patched); instances that do not
close in 600 s on more than 3 leaves (then the encoding is not local enough:
report, do not add time).

Metric (verbatim from the WP brief): One file wp3/logs/wp32/<id>.json per
certificate and per control, with fields: status (UNSAT / SAT / timeout),

the counter-completion plus the engine.py replay verdict (violation /
not-a-violation). Grading: P1/P4/P5 count of UNSAT among the listed ids;

reject reason; P6 max and median solve_s over all instances, count with
solve_s >= 600; P7 exact Fraction output of lp.py over the set of certified
types, compared with 259/86; P8 drat_status values; P9 git log of wp3/gesat/
after the frozen stamp, plus the re-run control logs. Mechanical agreement
check: every SAT counter-completion is passed to engine.py; a SAT that the
engine replays as not-a-violation counts as an encoder bug (spurious), not a
finding.
